# 美术评审报告 — 2026-06-10

**项目:** 自走棋 Roguelike (TypeScript + Phaser 3, 800×450)
**评审人:** Art Director
**评审范围:** 精灵图 7 批次 + Chibi 程序生成 + Theme 色彩体系 + 全场景截图 + 动效代码

---

## 一、视觉风格一致性

**评分: 3 / 10**

### 核心问题：两套视觉语言并存且无桥接

游戏同时运行两套完全不同的视觉语言，且在战斗场景中直接并列展示，造成严重的风格断层：

**手绘精灵图层（authored spritesheets）**
- 分辨率：约 120×120 px 每帧（600×600 图册，5×4 帧布局）
- 画风：细致的 AI 辅助手绘像素风，拥有丰富的笔触细节、体积光、多层次明暗渐变
- 代表作：`hero_mage_spritesheet.png`（first-batch）——红袍法师，布料皱褶、火焰特效、面部表情均清晰可辨；`enemy_frost_queen_spritesheet.png`（fifth-batch）——冰雪女王，蕾丝花纹与冰晶粒子极为精细；`hero_ice_dragon_hunter_spritesheet.png`（final-batch）——毛皮质感与冰龙特效达到整批次最高水准

**程序生成 Chibi 层（pixel-templates.ts + UnitRenderer.ts）**
- 分辨率：16×20 原始像素，渲染为 32×40（普通）/ 36×44（tank）/ 48×69（boss）
- 画风：极简主义像素人偶，最多使用 14 种调色板索引，通体以色块填充为主，无任何手绘质感

**直接证据：**
`docs/screenshots/battle.png` 与 `verify-phase1-battle-monsters.png` 显示：战场左侧英雄为 Chibi 像素人偶（~40px 高），战场右侧敌人也是同款 Chibi。所有 authored spritesheets 完全没有出现在实际游戏战斗画面中——它们存在于 `public/assets/units/` 目录但代码中并未使用。这意味着玩家在游戏中只看到程序生成的 Chibi，而制作团队已经产出了 50+ 张高品质精灵图却都在等待集成。

**批次内部一致性（仅评审精灵图本身）：**
- First-batch（hero_mage、hero_archer 等）：比例、线条宽度、特效风格一致，评分 7/10
- Second-batch（hero_knight）：与 first-batch 同框架但轮廓线略粗，色彩更暖，轻微漂移
- Third-batch（hero_necromancer）：整体风格最统一，暗色调、紫色系与主题契合，8/10
- Fourth-batch（hero_dragon_knight）：精灵体型明显膨胀，占据更多帧面积，比例与 first-batch 不一致
- Fifth-batch（enemy_frost_queen）：精细度最高，但与 first-batch 的 goblin 风格差距明显——goblin 使用有机粗犷线条，frost_queen 使用精密几何纹样，若出现在同一场景会显著失调
- Sixth-batch（hero_magma_warden）：完全转向石质/岩浆生物风格，与人类英雄同批次但视觉差异如同两个游戏
- Final-batch（hero_ice_dragon_hunter）：品质巅峰，但体型比 first-batch 英雄大 30%+

**Prototype 精灵图（prototypes/hero_warrior_spritesheet.png）：**
纯蓝色极简像素骑士，与 authored 批次完全不同，属于原型验证素材，不应与商业资产混存于同一目录层级。

**小结：** 批次间风格漂移（比例膨胀 + 精细度提升 + 色调偏移）是可接受的迭代现象，但程序 Chibi 与手绘精灵图的并存且无集成路径，是影响商业品质的结构性问题。

## 二、色彩体系

**评分: 6 / 10**

### 优点

`src/ui/Theme.ts` 的色彩架构设计合理，层次清晰：
- **元素色系（element）**：fire `#ff6b35` / ice `#35c9ff` / lightning `#ffeb3b` / dark `#9c27b0` / holy `#ffd700`——色相分布良好，彼此对比充足，战场元素标签可辨识
- **稀有度色系（rarity）**：common 灰 → uncommon 绿 → rare 蓝 → epic 紫 → legendary 橙，遵循行业惯例（类 Hearthstone），商店卡片边框颜色编码在截图中清晰有效
- **色盲模式**：`COLORBLIND_ELEMENT / RARITY / ROLE / NODE` 四套备用调色板已实现，且有符号辅助（elementSymbol），无障碍设计完善，这是明显亮点
- **背景色（#1a1a2e）**：深蓝近黑，配合战斗场景的墨绿背景形成一定层次感

### 问题

1. **holy 与 gold 颜色冲突**：`holy: 0xffd700` 与 `gold: 0xffd700` 完全相同。金币数值（右上角 "80G / 128G"）使用 gold 色，元素标签若使用 holy 也是同色，玩家无法区分货币信息与神圣元素信息——在 `docs/screenshots/battle.png` 中可见战场右侧 "☆光" 标签与金币数字颜色相同。

2. **战斗场景背景色氛围单薄**：当前背景为纯色 `#0a2a0a`（暗绿），无纹理、无渐变、无景深暗示。对比精灵图中丰富的视觉信息密度，背景显得极其贫乏，加剧了画面失衡感。

3. **幕次主题色未实现差异化**：4 幕（魔法森林 / 冰雪山脉 / 地下城 / Boss 幕）理论上应有色调区分，但从截图来看地图场景背景均为同一深蓝色 `#1a1a2e`，幕次沉浸感缺失。

4. **节点色（node）的 battle 与 boss 区分度低**：`battle: 0xcc4444` / `boss: 0xff2222`——两者均为红色系，亮度差约 15%，在小尺寸地图节点图标（约 20px 直径）上难以快速区分。从 `docs/screenshots/map.png` 可验证。

5. **UI 背景色层次压缩**：`background: 0x1a1a2e`（场景背景）与 `panel: 0x16213e`（面板背景）色差仅约 4%，面板在场景上"悬浮感"不足。`panelBorder: 0x0f3460` 虽然更深，但与面板色反差也有限——在商店、英雄征召场景可见面板几乎融入背景。

## 三、视觉层次与可读性

**评分: 5 / 10**

### 战斗场景（battle.png、verify-phase1-battle-monsters.png、fix-03-battle-1920.png）

**焦点引导失效：** 战场中央大面积留空（800×450 画布中，实际战斗角色仅占左侧 1/4 和右侧 1/8 区域），视觉重心分散。Chibi 人物在 ~40px 尺寸下几乎成为画布上的小点，无法形成视觉锚点。

**信息层次分析：**
- Layer 1（最高优先级，应最显眼）：金币、当前波次、速度倍率——金币位于右上角金色，可辨识；速度按钮（"1x"）合理；但幕次祝福文字与标题同行，字号几乎相同，缺乏层次
- Layer 2（次要信息）：左侧英雄生命条 + 右侧敌人生命条——颜色编码有效（蓝色方块 = 英雄 / 红色方块 = 敌人），但条宽仅 40px，5px 高，在战斗激烈时难以一瞥扫读
- Layer 3（参考信息）：技能栏底部——深蓝底圆形 + 汉字，在 `DEPTH.SKILL_BAR = 101` 层，与战场底色对比尚可，但技能冷却显示的 "0%" 文字（9px）极小，辨识困难

**fix-03-battle-1920.png** 显示在宽屏（1920px）下，战场两侧精灵图与 Chibi 并排出现时，authored 精灵图（骑士、弓手）明显比 Chibi 敌人精细度高出 10 倍，此对比在宽屏下更加刺眼。

**UI 面板质感（商店、英雄征召、休息）：**
- 纯色圆角矩形为主体，`UI_SIZES.CORNER_LG = 8px` 圆角——过于现代 Web 风格，与像素游戏调性割裂
- 无任何像素风格装饰元素（铆钉、羊皮纸纹理、金属边框、像素图标边框）
- 商店卡片（`verify-03-battle-hud.png` 中的商店面板）：稀有度颜色编码边框有效，但卡片内部空白过多，6 张卡片布局在 800px 宽度下密度感不足
- 休息场景（`e2e-2026-06-08-07-rest.png`）：3 个选项按钮为绿/蓝/橙纯色大矩形，缺乏游戏化设计感，更接近管理后台 UI

**英雄征召场景（verify-06-herodraft-chibi.png）：**
- 锁定英雄使用橙色锁图标，视觉噪音较大——15+ 个锁图标构成橙色点阵，抢夺对可解锁英雄的注意力
- 解锁条件文字约 9px，在深色背景下灰色文字对比度不足（`textDim: #999999` on `panel: #16213e`，对比度约 3.5:1，低于 WCAG AA 标准 4.5:1）

**地图场景（map.png）：**
- 节点图标语义编码良好（绿色钻石 = 商店、红叉 = 战斗、蓝心 = 休息）
- 连接线（近期 PR #12 已修亮）在截图中可见，可辨识度有改善
- 当前节点高亮（白色外圈）清晰，路径决策信息层次合理
- 唯一问题：章节标题 "第1章: 魔法森林" 与地图内容标题 "第1章: 魔法森林" 重复出现，信息冗余

## 四、动效与反馈

**评分: 6 / 10**

### 优点（基于代码分析）

**打击感工具链完整：**
`BattleEffects.ts` 实现了以下机制，设计意图良好：
- `hitFlash()`：`flashColor(0xffffff, 50ms)`——受击闪白，时长合理（50ms 不会拖拽感）
- `hitKnockback()`：12px 推开 + yoyo 回弹，持续 100ms——手感设计正确，符合像素风格的弹性节奏
- `critSlowMotion()`：`timeScale = 0.5`，持续 150ms——慢动作时窗适中，不打断战斗节奏
- `critEdgeFlash()`：30px 宽金色边框渐隐，250ms——边缘暗角设计经典，视觉区域与游戏核心区域不重叠，非侵入式
- `screenShake()`：intensity 0.005，100ms——参数保守，不晕眩，对快节奏自走棋合适

**DamageNumber.ts 工程质量高：**
- 对象池（WeakMap，POOL_MAX = 32）防止 GC 抖动，移动端友好
- 暴击专属表现：`CRIT!` 前缀 + 24px 粗体 + `SCALE.CRIT_INITIAL = 1.6` 放大冲击 + 4 个金色星形粒子（`*`字符模拟）——层次感有
- 连击文字（combo >= 5 显示 "x{n} COMBO!"）：附在伤害数字下方，不抢主体

### 问题

1. **技能特效单一：** `showProjectile()` 使用 4px 实心圆作为弹丸，所有职业弹道视觉相同，仅靠颜色区分。对比精灵图中法师的火球光环、骑士的光剑挥斩动画，程序生成的战斗特效极其简陋。

2. **AOE 特效无差异化：** `showAoeBlast()` 对所有 AOE 技能输出同一个扩散圆，`color` 参数虽可变但形状完全相同。火焰 AOE 与冰冻 AOE 在视觉上无法区分形态。

3. **技能施放无预读动画：** `showSkillName()` 仅浮出文字名称，没有施法蓄力的视觉预警（充能光效、目标锁定圆等），玩家无法预期技能即将触发。

4. **元素反应无专属特效：** `screenFlash(color, 150ms)` 统一处理所有元素反应——点燃/冻结/感电/腐化使用同形态全屏闪色，无形状/粒子差异，元素系统的深度信息无法通过视觉传达。

5. **Combo 伤害数字节奏欠佳：** `comboText` 的 `y + 14` 偏移使连击文字出现在伤害数字正下方，两个文字向上漂浮时重叠概率高，特别是在多单位同帧触发时。

6. **`reduceMotion` 旁路过于激进：** screenShake、critEdgeFlash、critSlowMotion、screenFlash 全部被 `reduceMotion` 屏蔽，但 hitFlash 和 hitKnockback 不受控制——前者是可接受的豁免，但后者对前庭敏感用户也可能有影响。

## 五、美术短板清单（按投入产出比排序）

### 排名 1：精灵图未集成到战斗场景（影响最大，属于已有资产浪费）

50+ 张高品质手绘精灵图存放于 `public/assets/units/` 但战斗中完全不显示，玩家始终看到 32×40 像素的 Chibi 人偶。这是单一最大视觉品质差距——不需要新建任何美术资产，仅需工程集成。

### 排名 2：战斗场景背景过于空洞

800×450 的战场背景为纯色 `#0a2a0a`，无任何场景装饰（地面线、场景元素、背景层次）。结合 Chibi 人物的微小体型，画面中 70%+ 是空白深色，无法传达战斗的紧张感与沉浸感。

### 排名 3：UI 面板缺乏像素风格语言

所有功能面板（商店、英雄征召、休息、事件）使用纯色圆角矩形，零装饰。与像素游戏调性不符，也缺乏品牌辨识度。

### 排名 4：技能/战斗特效与精灵图品质不匹配

精灵图自带丰富的动作帧（技能动画、施法特效），但程序生成的战斗特效（4px 弹丸、扩散圆）与之差距悬殊。

### 排名 5：Holy/Gold 颜色冲突 + 节点色区分度不足

两处颜色语义歧义（0xffd700 双重用途；battle/boss 红色过近）影响信息可读性。

## 六、优化建议

### P0 — 影响品质底线（必须修复）

**P0-1：集成 authored 精灵图到战斗场景**
- 问题：已产出 50+ 张高品质精灵图，但战斗场景完全使用程序生成 Chibi，形成资产浪费与品质底线缺失
- 方案：在 `BattleScene` 中按角色 ID 匹配 `public/assets/units/{batch}/{id}_spritesheet.png`，替换或叠加 Chibi 渲染；若仍保留 Chibi 作为 "低资源模式"，至少应让有对应精灵图的英雄使用手绘版
- 预估工作量：后端工程 3-5 天（资产加载器 + 帧映射 + UnitRenderer 切换逻辑），美术确认帧数定义 1 天
- 负责方：`technical-artist` 实现，`art-director` 验收帧映射

**P0-2：解决 Holy/Gold 颜色冲突**
- 问题：`Theme.colors.holy = 0xffd700` 与 `Theme.colors.gold = 0xffd700` 完全相同，货币与神圣元素无法视觉区分
- 方案：将 holy 改为 `0xfffacd`（柔和奶油金）或 `0xf0e68c`（卡其金），与货币金（0xffd700 暖黄）拉开 15% 色相差距；同步更新 `COLORBLIND_ELEMENT.holy`
- 预估工作量：代码修改 0.5 天，视觉验证 0.5 天

**P0-3：解锁条件文字对比度达标**
- 问题：`textDim #999999` on `panel #16213e` 对比度约 3.2:1，低于 WCAG AA（4.5:1）；英雄征召锁定英雄的解锁提示文字约 9px，不可读
- 方案：将该场景下的解锁文字改用 `#bbbbbb` 或 `#cccccc`，或将卡片背景略微提亮至 `#1e2d50`
- 预估工作量：Theme + 相关 Scene 修改，0.5 天

---

### P1 — 显著提升

**P1-1：战斗场景背景添加最简地面分层**
- 问题：纯色背景使战场空洞，角色"漂浮"在色块上
- 方案：添加两层：① 地面线（约 y=530，2px 高度渐变条，颜色比背景亮 15%）；② 远景色块（顶部 30% 区域做一个 40% 透明度的暗色渐变）。可纯程序绘制，无需美术资产
- 预估工作量：`BattleScene` 背景绘制代码 1 天
- 注：4 幕次应使用不同地面/天空颜色主题（森林绿/冰蓝/岩灰/熔岩红）

**P1-2：UI 面板添加像素风格边框装饰**
- 问题：纯色圆角矩形与像素游戏调性不符
- 方案：统一为 `Panel.ts` 添加可选的 "像素边框" 样式——在面板四角绘制 4×4 像素的角花（使用 `panelBorder` 色），顶部添加 1px 亮色高光线，底部添加 1px 暗色阴影线。不改变现有布局，仅叠加装饰层
- 预估工作量：`Panel.ts` 修改 + 视觉规范文档 1.5 天

**P1-3：元素反应特效差异化**
- 问题：所有元素反应使用同形态全屏闪色
- 方案：为 4 种反应设计专属形态：点燃（上升火星粒子 + 橙色屏闪）/ 冻结（放射状冰晶线段 + 蓝色屏闪）/ 感电（锯齿线段 + 黄色屏闪）/ 腐化（向下落尘粒子 + 紫色屏闪）；均在 `BattleEffects.ts` 中实现，复用现有粒子机制
- 预估工作量：`BattleEffects.ts` 新增 4 个方法，`technical-artist` 实现，2-3 天

**P1-4：节点色 battle/boss 视觉区分**
- 问题：battle（`#cc4444`）与 boss（`#ff2222`）同为红色，小图标难以区分
- 方案：Boss 节点改用红色 + 特殊形状（8 芒星或骷髅图标），而非仅靠色差区分；或将 boss 色改为深红 + 金色外框叠加（与 boss 血条 `healthbar.boss.borderColor: 0xffd700` 保持一致）
- 预估工作量：`MapScene` 节点绘制逻辑 + `Theme.ts` 修改 1 天

**P1-5：批次间比例标准化文档**
- 问题：first-batch 到 final-batch 英雄体型膨胀约 30%，若集成后尺寸不一会造成战场视觉混乱
- 方案：制定精灵图集成标准：① 所有英雄以 `hero_archer`（first-batch）为基准，定义标准帧边界框；② 新批次精灵图在集成前按基准缩放；③ Boss 允许 1.5× 放大
- 预估工作量：美术规范文档 0.5 天，各批次核查与标记 1 天

---

### P2 — 锦上添花

**P2-1：主菜单添加视觉标识**
- 问题：主菜单（`main-menu.png`）仅有两行文字标题 "自走棋 / 自动战斗"，无任何 Logo、装饰图形或动态元素，首次印象薄弱
- 方案：设计一个像素风格 Logo（含武器/皇冠图案），或在标题后方添加环境粒子（浮动星点 / 魔法光尘）；按钮可添加悬停光晕效果
- 预估工作量：美术资产 1-2 天，集成 1 天

**P2-2：战斗胜利/失败画面丰富化**
- 问题：`reward.png` 中胜利画面仅为文字列表，无视觉庆典感
- 方案：添加粒子爆发（复用 `BattleEffects.screenFlash` + 扩展金色粒子下落），或使用 authored 精灵图的胜利姿势帧（"胜利动画帧" 应在精灵图集成后可用）
- 预估工作量：2 天

**P2-3：伤害数字字体替换**
- 问题：`DamageNumber.ts` 使用 `fontFamily: 'monospace'`，系统等宽字体在像素游戏中显得格格不入
- 方案：引入一款像素风位图字体（如 Press Start 2P 或 Pixel Game 字体），仅用于伤害数字和战斗浮字，体积约 50KB
- 预估工作量：字体引入 + TextFactory 修改 1 天

**P2-4：Prototype 精灵图归档**
- 问题：`public/assets/units/prototypes/hero_warrior_spritesheet_before_idle_fix.png` 等旧版本资产混存于生产目录
- 方案：将 prototypes 目录移至 `docs/` 或 git 历史，清理 `public/` 目录
- 预估工作量：0.25 天
